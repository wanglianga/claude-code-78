# 阳光幼儿园 · 晨检接送与临时托管协同平台

## 原始需求

> 设计幼儿园晨检接送与临时托管交接页面，可使用 Vue 3、TypeScript 和 Pinia。家长送园时，保健老师记录体温、咳嗽、皮疹、用药、早餐、情绪和是否携带特殊物品；班主任看到晨检结论后，安排幼儿入班、观察或建议回家。接送页面记录家长、祖辈、保姆、临时授权人和接送照片，防止未授权人员接走。若幼儿发热、家长临时改接、药品服用时间变更、午睡异常、同班传染病提醒、晚接超过规定时间或临时托管到其他班级，页面要让保健老师、班主任、门卫、园长和家长围绕同一幼儿状态协同处理。离园后，接送人、用药执行、异常观察、托管交接和家长确认进入当日记录，用于第二天晨检和班级安全复盘。页面还要记录班级老师交接、校车儿童、园内活动、传染病班级观察和家长沟通记录。幼儿园的每一次接送变更都会影响门卫、班主任和家长端显示，不能让某一端还停留在旧授权。页面还要支持老师手持设备、门卫大屏和家长端三种视图，关键状态必须实时一致；如果网络异常，门卫端要能离线记录接送并在恢复后补同步。

---

## 一、技术栈与架构

- **前端**：Vue 3 + TypeScript + Pinia + Vue Router + Vite，纯 SPA，无需构建期外部依赖。
- **后端**：Node.js + Express，单进程同时提供 REST API、SSE 实时事件与静态资源。
- **数据库**：SQLite（better-sqlite3，WAL 模式），数据落盘到 Docker 卷 `/data`，重启不丢；**无额外数据库/缓存容器**，一条 compose 即可起。
- **实时一致**：服务端 SSE 事件总线（`/events?token=…`），任何写操作广播一条 `sync` 事件，所有在线端（老师手持、门卫大屏、家长端）收到后拉取**同一份快照**（`/api/state`），从机制上保证"某一端停留在旧授权"不会发生；SSE 断开时前端自动降级为 10 秒轮询。
- **登录即就绪**：登录成功服务端签发会话 token（`sessions` 表），前端立即用该 token 拉取快照并建立 SSE——家长、门卫、老师从登录页进入后**无需刷新**即看到业务内容；所有 `/api/*`（除健康检查/登录）与 SSE 都强制鉴权，401 自动回登录页。
- **临时授权接送**：家长申请必须提交关系/身份证照片/当日有效时间窗/原因；班主任核身批准后服务端生成一次性授权码与"授权来源"；门卫端显示来源与有效期，放行需"授权码 + 接送照片"，落库记录门卫确认人；到期自动恢复原名单、临时人不可再刷；全部授权记录（含证件照、申请人、核身人）留存当天档案。
- **接送放行服务端门禁**：不信任任何客户端身份字段。门卫在线核验授权码 → 服务端校验"当日有效授权人（临时授权另校验时间窗）∧ 当前有效接送计划匹配 ∧ 授权码正确"后签发**一次性放行令牌**（`pickup_verifications`，放行成功即作废）；放行接口只接受令牌 + 接送照片，姓名/关系/`pinVerified` 全部由服务端从数据库反查落库。无会话、非门卫角色、未核验、令牌失效/重用、授权人与计划不匹配（旧授权）、缺照片，一律 4xx 且**接送计划与门卫流水均不变**。
- **门卫离线**：门卫联网时先领取**当日离线许可**（`gate_offline_permits`，仅门卫会话可领）；断网期间只能从本机最后同步的**当日授权名单**中选人并拍照，事件带 `clientId` 存 localStorage outbox。恢复后 `POST /api/sync`（门卫会话 + 离线许可）先对整批做只读门禁预校验（授权匹配 + 照片），任一不通过整体 4xx 不写库；全部通过才事务落库，按 `clientId` 幂等，并以**设备登记时刻**（非补传时刻）记录离园时间与晚接判定。

```
浏览器（手持/大屏/家长端）
   ├── REST  /api/*            Express + better-sqlite3 ── /data/app.db (卷)
   ├── SSE   /events  ◀──────  事件总线 broadcast()
   └── 断网 → localStorage outbox ──恢复──▶ POST /api/sync（幂等）
```

## 二、一键启动（宿主 docker compose）

```bash
cp .env.example .env        # 已内置 CC_PUBLISH_PORT=3078，可按需修改
docker compose up -d --build
```

查看健康状态与实际映射端口（不要硬编码端口）：

```bash
docker compose ps
docker compose port app 4000
# 浏览器打开 http://host.docker.internal:<映射端口>/  或 http://localhost:<映射端口>/
```

容器以**非 root 用户 node（uid=1000）**运行，内置 `HEALTHCHECK`，健康通过后状态显示 `healthy`。

验证结束释放资源：

```bash
docker compose down          # 保留数据卷
docker compose down -v       # 同时清空数据，下次启动重新写入干净演示数据
```

## 五、关键业务流验证路径（建议按顺序体验）

1. **晨检 → 班级处置联动**：用 `health` 给陈安安补晨检，体温填 37.8，结论选"建议回家"保存 → 切到 `teacher1/guard/principal/parent1` 任一端，顶部预警条与孩子状态**实时出现**（无需刷新）。
2. **药品时间变更**：保健或班主任把朵朵 12:30 的药改到 13:00，或班主任点"确认喂药" → 家长端实时看到新时间/已服用。
3. **临时改接（防止旧授权接人）**：`parent` 端提交"临时改接"——必须填写授权关系（祖辈/保姆/临时亲友）、**身份证照片**、**当日有效起止时间**、接送原因、手机/证件尾号 → `teacher1/2` 在"审批沟通"里放大核对证件照、勾选"已电话向家长复核且人证一致"后核身批准 → 系统**服务端生成**一次性 4 位接送授权码，建立临时授权（来源记录为"临时授权·关系·申请人·核身人"），原计划立即置为"旧授权已作废"；门卫大屏上孩子的有效接送人瞬间切换，姓名旁显示 📎 授权来源与有效期。只有新授权码才能核验放行；接走照片与**门卫确认人**一并写入当日接送记录，证件照与整条授权（含待核身/已驳回）保留在"📒 当日记录 → 当天临时授权接送档案"。**有效期一到，下次任意端拉取快照即自动恢复原接送名单**（临时计划置 expired、临时授权人停用），临时人再次刷码返回 403/404 无法入园。
4. **未授权拦截**：门卫对来人直接"拒绝放行"登记 → 班主任/园长端立即收到拦截报警。
5. **晚接预警**：实际离园时间晚于规定 17:30 自动判晚接（见门卫大屏红色行与园长晚接监管）。
6. **临时托管**：班主任把某幼儿托管到其他班级并"登记返班" → 园长监管、家长端、门卫大屏同步显示托管状态。
7. **当日记录**：保健/班主任/园长右上角"📒 当日记录"，按幼儿汇总晨检、用药执行、异常观察、托管交接、接送人与照片、门卫流水、家长沟通；底部为传染病/交接/预警/拦截/晚接的班级安全复盘，可打印，供次日晨检对照。

## 六、门卫离线 → 补同步专项验证（核心需求）

门卫页面右上角点击 **"📶 模拟断网"**（点击时会先用门卫会话领取当日离线许可；也可直接拔网，浏览器会自动识别 `offline` 事件）：

1. 断网期间选择幼儿 → 从**本机当日授权名单**中选择来人（不能手填姓名）→ 核对证件 → 拍照 → "离线登记放行"；也可登记"拒绝放行"。
2. 页面顶部出现红色离线横幅，左侧"本机接送记录"出现**待补传**条目（计数徽章实时显示）。
3. 点击"演示断网中（点击恢复）"或网络恢复：前端自动携带离线许可调用 `POST /api/sync`，服务端对整批重新做授权匹配+照片门禁，条目变为"已补同步"，大屏出现"离线补传"角标。
4. 服务端对同一事件**重复补传幂等**（`client_id` 唯一约束 + 门卫流水双保险），按设备登记时刻记录，不会因补传时刻错判晚接；授权时间窗也按**登记时刻**判定——登记时在有效期内、补传时刚好到期的临时授权仍合法落库（并记许可门卫为确认人）；若断网期间发生过临时改接导致旧授权失效，或登记时刻本身不在授权窗内，该条补传会被 403 拒绝并保留在队列中，提示到园人工复核，**绝不用旧授权放行**。

接口层已验证的例子（门卫会话 + 当日离线许可，登记时刻 18:05 晚于 17:30）：

```bash
# 1) 门卫登录取会话 token
GUARD_TOKEN=$(curl -s -X POST http://<host>/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"guard","password":"123456"}' | jq -r .token)
# 2) 联网时领取当日离线许可
PERMIT=$(curl -s -X POST http://<host>/api/gate/offline-permit -H "Authorization: Bearer $GUARD_TOKEN" | jq -r .permitToken)
# 3) 恢复网络后补传（permitToken + personId + 照片缺一不可）
curl -X POST http://<host>/api/sync -H "Authorization: Bearer $GUARD_TOKEN" -H 'Content-Type: application/json' -d '{
  "permitToken":"'$PERMIT'",
  "events":[{"clientId":"offA","type":"checkout",
    "createdAt":"2026-09-15T18:05:00+08:00",
    "payload":{"childId":"c_kangkang","personId":"ap_kangkang_mom","photoUrl":"data:image/jpeg;base64,..."}}]}'
# → {"ok":true,...,"late":true}；再次发送同一 clientId → duplicated:true；
#   无许可/无照片/旧授权 → 401/400/403，整批不写入。
```
